# Word Rogue

A roguelike deckbuilder where you build real English sentences from word cards — correct grammar is the combo engine. Arabic-first, CEFR A1→B1, Expo / React Native / TypeScript, Android.

## Status

**M0 — scaffold.** The app runs, CI is green, and the lint boundaries are enforced. The grammar engine lands at M2, corpus first.

## Documents

- `docs/word-rogue-requirements.md` — the SRS. Source of truth, referenced by requirement ID.
- `docs/word-rogue-brief.md` — the concept brief the SRS derives from.

## Layout

See `TEC-006`. The short version:

| Path | Contents |
|---|---|
| `app/` | expo-router screens. Layout and dispatch only — never rules. |
| `components/` | Presentational components. `components/ltr/` holds the LTR islands. |
| `constants/` | Theme tokens. No literals elsewhere. |
| `lib/engine/` | Grammar engine core. Framework-free. |
| `lib/run/` | Encounter loop, run state, economy. Pure reducers. |
| `lib/rng/` | Seeded `xoshiro128**` streams. |
| `lib/i18n/` | Locale strings, direction, bidi and digit helpers. |
| `lib/platform/` | The only place a native or Expo module is imported. |
| `data/` | All content and balance JSON. |
| `tools/` | Node CLIs run with `tsx`. |
| `tests/` | Vitest suites and the golden corpus. |

## Boundaries worth knowing

These are lint-enforced, not conventions:

- Nothing in `lib/engine`, `lib/run` or `lib/rng` may import React, React Native, Expo or a Node built-in (`TEC-007`). The same files run in the app, in `tools/`, in tests, and on the server that verifies leaderboard submissions.
- `Math.random()` appears nowhere (`TEC-010`). All randomness comes from a named seeded stream.
- No locale-dependent API — `Intl`, `toLocaleString`, `localeCompare`, `Date` — inside the engine core (`TEC-026`).
- No physical edge properties (`marginLeft`, `right`, …) in screens or components (`TEC-063`). Use `marginStart` / `end`, so RTL mirrors for free.
- Every touchable is `components/Pressable48.tsx` (`UI-047`), which enforces the 48 dp minimum and a required accessibility label.

## Development builds

Billing is a native module, so the app runs in a **development build**, not Expo Go (`TEC-045`). `android/` is generated by `expo prebuild` and never committed.
